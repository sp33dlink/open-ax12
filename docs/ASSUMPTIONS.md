# Assumptions to verify on the real AX12

Nothing below has been checked on the device yet. Each item should be confirmable from the
Diagnostics screen. Append new items when you rely on unproven behaviour; mark them
`VERIFIED` / `WRONG` (with date) once tested.

| # | Assumption | Where it matters | Status |
|---|---|---|---|
| 1 | The stock RadioMaster app must be force-closed/disabled; only one process can open the serial port. | Startup, diagnostics hint | open |
| 2 | The demo's serial-port workaround (redirect `TMPDIR`, NOP two instructions in `libQt6SerialPort` at +0x15628 / +0x15648) is required and sufficient. | `:sdk` JNI | open |
| 3 | Switch sources report their position as a logic value of −100 / 0 / +100 (up / mid / down). | Switch UI, conditions, compilers | open |
| 4 | A switch can be used as a mix **input** through a custom curve (per-position offsets). | Flight-mode / flaps compiler | open |
| 5 | A channel holds at most one mix per source (`rcDelMixCfgData` is keyed by `(chIdx, srcIdx)`). | Managed mixes | open |
| 6 | The maximum number of mixes per channel is unknown; the UI reads `mixesCount` and handles a failed add. | Mixes tab, compilers | open |
| 7 | `RC_MSGID_CRSF_DATA_RECEIVED` delivers all telemetry frames (incl. vario 0x07 / baro 0x09). | Vario, sensors | open |
| 8 | `rcSet*` changes are previewed live on the device before saving. | Dirty state, discard | open |
| 9 | A text-to-speech engine is installed on the AX12. | Voice | open |
| 10 | The SDK only works with an app-private `appDataPath`; the public model library is a mirror. | Model storage | open |
| 11 | Output channel count is 16 and channel values are ±100 % scaled as `chOut`. | Channel displays | WRONG 2026-11-21: 16 channels confirmed, but `chOut` is the PWM pulse in µs (1000..2000, 1500 = centre); converted in `SdkAssumptions.channelPercent`. |
| 11a | `stickMode` codes are reversed: 1 = Mode 2 (throttle left), 2 = Mode 1. Observed 2026-11-21: a physically Mode 2 AX12 reported `stickMode = 1`, and with the documented reading the vertical axes of the two stick pads were swapped. Check: switch the stick mode in the stock app and confirm the code changes to 2. If instead the code stays 1 and the sources follow the physical sticks, the pads must ignore the mode. | Stick pads, calibration, simulator, System → stick mode | open |
| 12 | Curve parameters: DIFF / EXPO / FUNC keep their single parameter in `yVal[0]` (differential %, expo %, function number) and behave as documented in `CurveMath`; `xVal[0]` is unused for these types (written as 0). Until verified, `CurveConfig.sameShapeAs` compares both `x[0]` and `y[0]`. Compare with `Radio.applyCurve` on the device (needs assumption 19). | Curve editor preview, simulator, compilers | open |
| 13 | `ElrsSetItemUI.type` carries the CRSF parameter type codes unchanged (9 = text selection, 11 = folder, 13 = command, …; `ElrsItemType`). | ELRS menu | open |
| 14 | Channel lock: `lockChSwType` uses the common compare codes (0 off / 1 > / 2 = / 3 <) with `lockChSwVal` as the compare value; timers use `switchAct` / `resetSwAct` the same way. | ChLock tab, timers, `SwitchCondition` mapping in the SDK bridge | open |
| 15 | `rcGetCurrentModelCfgIndex()` (a plain `int`) identifies the current model either by its `modelIdx` (an `int64` in `RcModelDataUI`) or by its position in `rcGetRcModelList()`. `Radio.getCurrentModel()` is the only resolver and tries both in that order. Check: compare with the model the stock app shows as active, with at least two models. | Model library reconcile | open |
| 16 | `chIdx`, `mixIdx`, `timeIdx` and DR `idx` are 0-based; `rawLogicVal` is the source value in percent (−100..+100). | Everything that indexes channels; live displays; conditions | PARTLY WRONG 2026-11-21: 0-based indices look right; `rawLogicVal` is an unusable constant on the AX12, `rawVal` is ±500 = ±100 % and absent sources report 65535. Logic percent is derived from `rawVal` (`SdkAssumptions.sourcePercent`). |
| 17 | The firmware mixer works as modelled in `MixerMath` (mix lines → dual rate → channel curve → weight → middle / limits → lock). Only the simulator and the "explain" line depend on it. | Simulator, Mixes "explain" | open |
| 18 | `rcGetDrData(chIdx, -1)` ("find a free slot") returns a value-initialized struct (`chIdx` 0, `idx` 0) when no slot is free or the call fails, and may not treat slots the app disabled as free (`rcDelDrData` is a no-op). The app never allocates with it: free = disabled, found by scanning the three slots (`Radio.findDisabledDualRateSlot`). Check: call it on a channel with 0 / 1 / 3 enabled slots. | DualRate tab, plan differ | open |
| 19 | `rcCurveApply(curveIdx, rawVal)` takes and returns **percent** (−100..+100), not half-scale raw units. Check: an identity custom curve (−100,−100) / (0,0) / (100,100) must return 50 for input 50 and clamp at ±100. | Curve editor marker, verification of assumption 12 | open |
| 20 | The SDK cannot create a model file with default settings: a new model is `rcCreateModelCfg` + `rcSaveCurrentCfgToModel`, i.e. a copy of the working config, which the first applied plan neutralises (`MixPlan.resetConfig`: no mixes, curves `NONE`, dual rates disabled, neutral channels, no locks, timers stopped). Things the API cannot set (source names / input weights) are inherited. Alternative to evaluate on the device: importing a stock template from `rcGetTemplateList()`. | Model creation | open |
| 21 | `rcGetTimerCfgData` / `rcSetTimerCfgData` take the **in-group** index 0..2 together with `isCounter` (manual 14.2); the header comment instead says "0-2 are timers, 3-5 are counters". Also unknown: whether `RC_MSGID_TIM_NOTIFY.timeIdx` is in-group or the device number 0..5. Each `Radio` implementation keeps the mapping in one function. Check: read counter 0 as `(0, isCounter = 1)` and as `(3, 0)` and compare with a known counter setting; watch `timeIdx` of a counter notification. | Timers tab, live timer / counter states | open |
| 22 | The "current model file" that `taskReadConfigFromDevice` overwrites and `taskSaveConfigToDevice` saves is the file loaded last with `rcLoadModelFile` (the model `rcGetCurrentModelCfgIndex` reports), and the choice survives an SDK restart. The model library keeps its own reference copy (`model.json`) to repair a file overwritten by a read while the device was out of sync. Check: load model B, do not save, read from device, inspect B's file. | Model switching, discard, reconcile | open |
| 23 | The value sets of `RcTimeCfgDataUI.mode`, `loopMode` and `outputMode` are undocumented. They are kept verbatim; the Timers tab shows them as plain numbers until identified on the device (compare with the stock app's timer settings). | Timers tab | open |
| 24 | A serial port held by the stock app is not reported as such by the SDK: it shows up as `InitResult::CommunicationInitFailed` or as a device timeout. `SdkRadio` may refine this (probing `open()`, `/proc/self/fd`), best effort only; the UI shows the "close the stock app" hint for every `ConnectionError.mayBeStockAppConflict`. Check: start with the stock app running and note the resulting error. | Startup error hint | open |
| 25 | Device values outside the documented sets can occur and must survive unrelated writes: `stickMode` other than 1 / 2, `rfModuleMode` `0xFF`, `lockChSwType` outside 0..3, unknown `mixesMode` / `cType` / `countdown` codes. The bridge writes an enum-mapped field only when its Kotlin value really changed. Check: Diagnostics lists the raw values. | Every SDK setter | open |
| 26 | The AX12's hardware volume control adjusts the Android **media** stream. `:core:audio` plays everything (speech, beeps, vario, sound files, music) with `USAGE_MEDIA` so one volume governs all of it. Check: turn the radio's volume down while the vario tone plays. | All sound | open |
| 27 | The AX12 audio output accepts a low-latency 16-bit mono `AudioTrack` at the rate reported by `AudioManager.PROPERTY_OUTPUT_SAMPLE_RATE` with roughly 25 ms queued. `TonePlayer` grows the buffer when it underruns and falls back to 48 / 44.1 kHz. Check: trim beeps and vario tone are free of crackle and follow the stick without noticeable delay. | Beeps, vario | open |
| 28 | The AX12 has a vibration motor reachable through the Android `Vibrator` service (`hasVibrator()`); without one, haptics are silently skipped. Check: System → haptics test. | Haptics | open |
| 29 | Home screen display conventions (`:feature:home`): trims (`Trims`) are percentages in -100..+100 of the trim range; a stick's vertical axis is +100 = up (throttle at the bottom reads -100); S1-S8 (sliders) are drawn 0..100 % from the left end of the arc (logic -100..+100 mapped), P1-P8 and CNT1-CNT6 centred; every enabled switch is drawn as a 3-position pill because `SourceInfo.type` does not say 2 or 3 positions; counters CNT1-CNT6 are shown through their source logic value in percent. Check: move each control on the radio and compare with the home screen and the stock app. | Home sticks, trims, switches, knobs | open |
| 30 | `SourceInfo.enabled` (`isEnable`) marks the sources that physically exist on the AX12; the home panel lists only those. If it is 1 for all 42 sources, the panel pages through non-existent inputs. Check: Diagnostics source list vs. the hardware. | Home input pages | open |
| 31 | The AX12's Android 9 build may ship **without a document picker** (`ACTION_OPEN_DOCUMENT` / `ACTION_GET_CONTENT` have no handler). `:feature:models` tries both and then shows "No file picker is available"; model import and picture selection are then only reachable through an `ACTION_VIEW` / `ACTION_SEND` intent from another app (e.g. a file manager). Check: Models → Import… and Model detail → Change picture on the radio. | Import, custom picture | open |
| 32 | The ELRS model-match number is edited as 0..255 (`MODEL_MATCH_MAX` in `:feature:models`); the SDK stores an unsigned 32-bit value and its real range is undocumented. A value above 255 read from the device is shown clamped but is not rewritten until the user edits it. Check: set 63 / 255 / 300 in the stock app and read it back. | Model detail | open |
| 33 | The share sheet (`ACTION_CHOOSER` with `ACTION_SEND`, `application/octet-stream`, FileProvider URI in `EXTRA_STREAM` and `ClipData`) exists on the AX12 and offers at least one target (e.g. Bluetooth, a file manager). Check: Model detail → Export. | Model export | open |
| 34 | `rcSetUsbToVcp(mode)`: mode `1` switches the USB serial passthrough on and `0` off (the manual only says "defined by the device protocol"). The state cannot be read back; the System screen keeps the last value it sent for the session only. Check: switch it on and see whether the module shows up on a computer; off must restore normal operation. | System → Radio | open |
| 35 | `rcSetAdcCalibration(false)` finishes the calibration and stores the result (there is no separate cancel), and `RadioStatus.calibrationState != 0` means "calibrating". `:feature:system` therefore finishes a running calibration when its screen is left. Check: start, sweep only part of the range, finish, and read the stick values in Diagnostics → Monitor. | Calibration screen | open |
| 36 | The receiver is addressed as CRSF device `0xEC` for `rcTaskRequestElrsMenuList` and answers only while the link is up; the CRSF command steps are start 1 / confirm 4 / cancel 5 / poll 6 and an acknowledgement `status` of 2 means "in progress", 3 "needs confirmation", anything else idle. Check: ELRS screen, receiver tab; run Bind and WiFi commands. | ELRS menu | open |
| 37 | The Diagnostics screen can show **mapped** device values only (`SystemConfig.stickMode.sdk` etc., see assumption 25): the `Radio` interface hides unknown raw codes. An unknown code is visible only indirectly (stick mode shows 2 for any code other than 1). Check: compare with the stock app's stick mode and RF module setting. | Diagnostics → Checks #25 | open |
| t1 | `GpsFix.groundSpeed` is in km/h (the CRSF GPS frame carries km/h x 10); the last-position screen converts it like a `SensorUnit.KMH` value. Check: compare with the GPS speed widget while a GPS is connected. | Last position screen | open |
| t2 | The AX12's Android 9 image may have no maps app, no share targets and no clipboard UI. "Open in maps", "Share" (position and CSV logs) start a plain `ACTION_VIEW geo:` / `ACTION_SEND` intent and show a toast when no activity handles it; copying coordinates uses `ClipboardManager` directly. Check: tap each button on the radio. | Last position, flight logs | open |
| t3 | The telemetry entries create their view models with `viewModel(key, factory)`. Without a Navigation 3 view-model decorator in the shell they live in the activity's store; the widget editor and alarm editor throw their draft away when the entry leaves the composition (`DisposableEffect`), the main telemetry screen keeps its edit mode / selected page on purpose. | Telemetry entries | open |
| t4 | Alarm thresholds, hysteresis and widget scale / warning values are in the sensor's native (metric) unit, as the runtime compares them (`ValueResolver.number`); a per-model unit override only changes how the value is displayed. | Alarm editor, widget editor | open |
| m1 | `rcSetMixCfgData` may change `srcIdx` of an existing line in place (header: it overlays `srcIdx`). The Mixes tab's Input cell relies on it and reads the line back; if the device keeps the old input the tab shows "could not change the input" (workaround: delete + add, which moves the line to the end). Generated lines keep their input. | Mixes tab | open |
| m2 | The curve editor sends every drag step of a point / slider with `rcSetCurveCfg` (only the latest value, never a backlog) and the SDK accepts that rate and previews it live (assumption 8). Check: drag a point while watching a channel bar. | Curve editor | open |
| m3 | The switch-condition editor offers Up / Mid / Down for every switch source; the middle position never occurs on a 2-position switch (the number of positions is not in `RcSrcCfgUI`; the meaning of `srcType` is unverified). | Mixes, DualRate, ChLock, Timers | open |
| m4 | Removing a channel lock writes `lockChSwType = 0` (assumption 14) and leaves `lockChSwIdx` / `lockChSwVal` / `lockChVal` as they were. | ChLock tab | open |
| 29 | `TelemetryRepository.sensorList` contains inputs, channels and timers as documented; the functions pickers add every enabled input, the 16 channels, timers, counters and the well-known telemetry sensors (`Sensors.templateNames`) themselves, so a logical switch or vario can be set up before the receiver ever reported a sensor. Check: Sounds → vario sensor picker with no receiver bound lists `VSpd`. | Logical switch, trigger and vario pickers | open |
| 30 | The app shell does not scope `ViewModel`s per navigation entry (no `rememberViewModelStoreNavEntryDecorator`): the editors (`LogicalSwitchEditor`, `SpecialFunctionEditor`, `VoiceAlertEditor`) therefore create their ViewModel under a key that is new on every open. With an entry-scoped store the key is harmless. Check: open L1, press Done, open L1 again: the editor must open, not close at once. | Editors in `:feature:functions` | open |
| 31 | A 2-position switch reports only −100 / +100 (assumption 3); flight modes on Middle of such a switch never become active and the compiler maps that position to the default mode. | Flight modes tab, `FlightModeCompiler` | open |
| a1 | `RadioService` uses foreground service type `mediaPlayback` (manifest + `startForeground` from API 29, permission `FOREGROUND_SERVICE_MEDIA_PLAYBACK` from API 34, nothing on API 28). `connectedDevice` needs a Bluetooth/USB/network permission the serial link lacks; `specialUse` needs a declared subtype. Check: service stays alive with the app in the background on the AX12; notification shows. | `:app` service | open |
| a2 | `RadioBackend.AUTO` means SDK exactly on API 28 with arm64-v8a (the AX12), simulator everywhere else (`BackendPolicy`). Check: Diagnostics shows the SDK backend on the radio. | `:app` | open |
| a3 | If `SdkRadio` cannot be constructed, `:app` falls back to the simulator (SIM badge) instead of crashing at start; the cause is only in logcat. | `:app` | open |
| a4 | The AX12 file manager sends `.oax12` as `application/octet-stream`, `application/zip` or with no useful type; the intent filters match all of these plus the `.oax12` extension. `singleTask` delivers a shared file to the running instance. Check: open a `.oax12` from the file manager. | Import | open |
| a5 | The notification's Quit action shuts the graph down and kills the process (frees the serial port, avoids re-initialising the Qt-based SDK in a live process). Check: stock app can open the port right after Quit. | `:app` | open |
| a6 | The screenshot special function uses `PixelCopy` on the activity window and writes `<library>/screenshots/<time>.png`. Not tried on API 28. | `:app` | open |
| a7 | `ActivityManager.killBackgroundProcesses("com.Flyshark.RadioMasterAX")` (normal permission `KILL_BACKGROUND_PROCESSES`, no prompt) ends the stock app's process on the AX12 and frees the serial port, because the stock app is in the background whenever open-ax12 is in front. Verified on the AX12 (Android 9): with the stock app running in the background and "Close the stock app automatically" on, open-ax12 connected on its own and the stock pid was gone. Not verified: that the stock app does not restart itself later (it holds `RECEIVE_BOOT_COMPLETED`; nothing else was seen to restart it), behaviour on Android 10+ (not relevant for the AX12), and a stock app that is in the foreground (cannot happen while ours is). | `:app` `StockApp` | verified on the AX12 |
| a8 | Whether the stock app *runs* cannot be detected (`/proc` is hidepid=2); the app therefore closes it blind. The automatic close happens right before every connect (500 ms settle), and once more (1 s settle) plus one retry when the start fails with a `ConnectionError.mayBeStockAppConflict`, which includes `DeviceTimeout`. A radio that is simply off or silent therefore takes two start attempts (about 2 x 30 s) before the error screen appears; with the setting off, or the stock package missing, there is a single attempt. | `:app` `RadioConnector` | open |
| a9 | With the stock app holding the port the SDK reports `SerialPortBusy` (`/dev/ttyS0: errno 16`) only after the 30 s initial-read timeout, so the "still connecting" hint (20 s) shows before the error does. The "Close stock app" button on that hint cancels the running `AppGraph.start()`, calls `Radio.stop()`, closes the stock app, waits 1 s and starts again from scratch (verified on the AX12: connected about 15 s later). The stock-app buttons are hidden when the package is not installed (emulator); `<queries>` declares the package for API 30+. | `:app` `RadioConnector`, startup screens | verified on the AX12 |
| r1 | Trim values are limited to ±100. | `:core:runtime` trim announcements | open |
| r2 | Firmware timer alert notifications are not rendered by the app; timer announcements come from the runtime engine's own evaluation. | `:core:runtime` | open |
| r3 | `resetToDefaults` refreshes the public library export through `onDeviceConfigWritten`. | `:core:runtime` `ConfigSession` | open |
| s1 | The SDK survives `shutdown()` followed by `initialize()` in the same process: `SdkRadio.start()` after an `Error` (including `ConnectionLost`) and `stop()` followed by `start()` do exactly that (the Qt `QCoreApplication` is created again, the serial port is reopened). Only `:app`'s Quit action avoids it by killing the process (a5). Check: start with the stock app holding the port, close the stock app, retry `start()`; also `stop()` then `start()` from Diagnostics. If the second `initialize()` crashes or never connects, restart the process instead of retrying in place. | `:sdk` `SdkRadio.start` / `stop` | open |
| s2 | `rcSetModelCfg` ("loads the target file, updates the metadata and saves it") and `rcImportModelCfg` do not replace the SDK's working config, or at least not its list sizes; `SdkRadio` therefore bumps no `configRevision` for them but does drop its cached list sizes (the basis of index validation, otherwise re-read every 2 s). Check: with the current model, call `updateModelInfo` / import into the current model's file and compare `getOutputChannels()` / mix counts before and after. If the working config changes, `configRevision` must advance there too. | `:sdk` `updateModelInfo`, `importModel` | open |
| s3 | `rcGetNotifyCfgList()` order is the index space of `rcSetNotifyCfgItem(hash, cfg, index)` and `rcDelNotifyItem(index)`. `SdkRadio.getTelemetryAlarms()` reports the list **position** as `TelemetryAlarm.index` and ignores the `idx` field of the items (it may be 0 for every item). Check: add two alarms, modify / delete the second one and confirm that the second one changed. | SDK alarm editor | open |
| s4 | The SDK output thread is a native `pthread` that ends through a normal thread exit (TLS destructors run): the bridge attaches it to the JVM once, on the first message, and the pthread-key destructor detaches it again. The payload of `RC_MSGID_TRIM_NOTIFY` is read as a single `uint8_t` (manual 8.2; the vendor demo never looked at it). Check: logcat shows no "Native thread exiting without having called DetachCurrentThread" abort after `stop()` / `shutdown()`; trim changes are announced. | `:sdk` message callback | open |
| s5 | One live frame (`RC_MSGID_MIXOUT_UPDATE`, about every 40 ms) costs four SDK reads (sources, channels, trims, status) in one JNI call and stays well below 25 ms on the AX12 CPU, because `rcGetSrcCfgList` / `rcGetChOutList` copy 42 + 16 structs with `std::string` members each time. Frames are conflated, so a slow device only lowers the frame rate. Check: Diagnostics frame rate while all inputs move. | `:sdk` live data | open |
