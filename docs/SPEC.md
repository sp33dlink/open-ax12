# open-ax12 feature spec

Reference screenshots of the stock app: `docs/reference/stock-home.png`, `docs/reference/stock-mixes.png`.
The owner flies fixed-wing gliders today; multirotor and helicopter must be supported too.
The app **replaces** the stock app (both cannot hold the serial port). Firmware updates stay in the stock app.

## 1. Look & feel

Stock look, cleaned up:

- **Light theme (default):** icy pale-cyan background (≈ `#DDF2F6`), soft raised "neumorphic" cards with large corner radii and soft double shadows (light top-left, dark bottom-right), dark navy text (≈ `#1B2B3A`), accent blue (≈ `#2F7FB5`), teal (≈ `#1FB8A6`) and orange (≈ `#F2A65A`) for switch states, green (≈ `#12A66A`) for channel bars in setup screens.
- **Model-setup chrome:** dark navy (≈ `#14283A`) top bar with back arrow, a scrollable tab row (selected tab is a light-cyan pill with rounded top corners), an outlined white **Save** button on the right; a dark navy column-header row under it.
- Also ship a **Dark** theme and a **High-contrast (sun)** theme; selectable in system settings.
- Top status bar on every screen: link bars + LQ %, centre title, RX voltage (plane icon), TX voltage (battery/cube icon), date/time.
- Bottom bar (icons only, like stock): System · Model setup · Models · **Home** · Telemetry · Touch lock · Help.
- Fixed virtual canvas 853×480 dp (`FixedCanvas`). Everything must fit without scrolling on Home.

## 2. Home screen (`:feature:home`)

Layout as in `stock-home.png`: left column (left stick pad, channel list), centre card (model name, picture, timers), right column (right stick pad, switches, knobs, page selector).

- **Stick pads (modernised — explicit owner request):** rounded square on the plain background (no card around it), subtle grid, position dot (no motion trail). The four borders are four separate segments: a border **lights up (accent glow) while the stick is at its maximum on that side** (exactly ±100 %, which also reveals sticks that need calibration), two borders in a corner. The **centre marker lights up while the stick is at dead centre** (both axes within ±2 %). Trim position shown as a small marker riding on the border itself (outer vertical edge and bottom edge) with a tick at the neutral position; the marker has a contrasting rim so it stays readable on a lit border. Which sources map to which pad follows the stick mode (mode 2: left = Thr vertical / Rud horizontal, right = Ele / Ail; mode 1: left = Ele / Rud, right = Thr / Ail).
- **Channel list:** CH01–CH08 with a centre-zero bar and %; pager to CH09–CH16. Channels with mixes are emphasised.
- **Centre card:** model name; model picture (custom picture or a default per model type). **Tapping the picture flips the card to the pinned telemetry widgets** (grid from `:core:widgets`); tapping again (or the small toggle) flips back. The choice is remembered per model. Timers T1–T3 with start/stop/reset by tap/long-press and a gear to the timer settings.
- **Right lower area:** switches as 3-position pills (orange up / neutral mid / teal down), knobs/sliders as arc gauges, page selector `1…6` that pages through all enabled inputs (SA–SP, P1–P8, S1–S8, counters) and a flight-mode/logical-switch page.
- Active flight mode name shown in the status bar title area. Tapping the model name opens Models.
- When the simulator backend is active a small "SIM" badge is shown.

## 3. Model setup (`ModelSetup` screen, tabs contributed by `:feature:modelsetup` and `:feature:functions`)

Chrome as in `stock-mixes.png`. **Save** writes to the device and persists the model (`ConfigSession.save()`); leaving with unsaved changes asks Save / Discard / Cancel. A dirty dot is shown on Save.

Tabs from `:feature:modelsetup`:

1. **Input check** — every enabled source with live raw/logic value, name, type; per-source pre-flight-check preset (value or "don't check").
2. **Output** — per channel: min, max, middle (subtrim), curve, weight/reverse, live bar.
3. **Mixes** — as in the screenshot: channel rows with live green bar; expanding a row shows its mix lines (`+=`/`:=`/`*=`, Input, Weight up/down, Offset, Curve, Switch condition, Mode, Slow up/down, Delete) and **Add input**. Lines generated by flight modes/flaps/wizards carry a "managed" badge and warn before manual edits. Includes a live **"explain"** line: how the channel value is composed.
4. **DualRate** — up to 3 slots per channel: switch condition + weight. Because the SDK cannot delete a slot, "delete" = disable (compare type 0) and the UI says so.
5. **ChLock** — channel lock (throttle cut / safety): switch, condition, locked value, per channel. Includes a one-tap "Throttle cut" helper.
6. **Curves** — list of the 18 curves and an editor: type (none / diff / expo / function / custom ≤ 12 points), draggable points, numeric entry, live preview with the current input marker (uses `curveApply`).
7. **Timers** — 3 timers + 3 counters: mode, start value, direction, switch/reset conditions, alert mode and interval, voice countdown options.

Tabs from `:feature:functions`:

8. **Flight modes** — see §7.
9. **Flaps / Wing** — see §7.
10. **Logical switches** — see §6.
11. **Special functions** — see §6.
12. **Sounds** — voice alerts list (text templates with triggers) and vario settings.

## 4. Models (`:feature:models`)

- Grid/list of models with picture, name, type, model-match id, last used. Current model highlighted.
- Create (from built-in template or blank), duplicate, rename, delete (confirm), select. Selecting a model while the link is up (LQ > 0) requires an extra confirmation; switching loads the model and writes it to the device.
- **Storage:** every model is a folder in the user-accessible library `…/OpenAX12/models/<name>/` containing `model.json` (the SDK model file), `extras.json` (`ModelExtras`) and `picture.jpg`. On API ≤ 29 the library root is `/sdcard/OpenAX12` (runtime storage permission); on newer API levels fall back to the app's external files dir. The SDK keeps its own private copy; the repository keeps both in sync (export after every save, import folders unknown to the SDK, detect externally modified folders and offer re-import).
- **Export / import:** export = zip of the model folder with extension `.oax12`, shared through the Android share sheet (`FileProvider`, `ACTION_SEND`). Import = app is a target for `ACTION_VIEW`/`ACTION_SEND` of `.oax12` / `application/zip` / `application/octet-stream`, plus an "Import…" button (document picker). Import validates the archive (no path traversal, schema version, size limits) and never overwrites silently. Stock-app model exports (`.json`/`.rcm`) can be imported as SDK-only models.
- **Custom picture:** pick from gallery/files, crop to the card aspect, downscale, store in the model folder.
- **Snapshots:** every save keeps a timestamped copy (keep last 20) with restore.
- **Built-in templates:** Glider (2/4/6-servo wing, V-tail or cross tail, camber + butterfly), Plane (ail/ele/thr/rud, optional flaps, differential), Flying wing (elevon), Multirotor (AETR, arm switch, mode switch, beeper), Helicopter (flybarless: collective, throttle curve / idle-up via mode switch, throttle hold). Templates are mix plans produced by `:core:engine`.

## 5. Telemetry (`:feature:telemetry`, `:core:widgets`)

- **Sensors:** unified registry of sensor values from three sources: the SDK telemetry list, decoded raw CRSF frames (GPS 0x02, vario 0x07, battery 0x08, baro alt 0x09, airspeed 0x0A, link stats 0x14, attitude 0x1E, flight mode 0x21, Rotorflight custom 0x88 as in the SDK demo), and internal values (TX voltage, LQ, dBm, timers, sticks/channels, flight mode, logical switches). Each sensor: id, name, value, unit, precision, min/max, age, lost flag. Per-model rename/unit/precision override. Reset min/max.
- **Telemetry tab:** pages of widgets on a grid (e.g. 6×4), edit mode with add / move / resize / configure / delete. Sensor list view. Alarm editor.
- **Widget types:** value, value with min/max, bar, arc gauge, sparkline/graph, battery (cells), link quality, timer, vario indicator, artificial horizon, GPS (coords, distance and bearing to home, open in maps), switch/logical-switch state, flight mode, text label.
- **Pinning:** each widget has a `pinned` flag; pinned widgets appear in the home centre card (§2).
- **Alarms:** threshold alarms with hysteresis and repeat interval → voice / beep / haptic / popup (app-side). Telemetry lost/recovered and low TX voltage are announced.
- **Logging:** optional CSV log per flight (EdgeTX-like columns) in `…/OpenAX12/logs/`.
- "Last known position" card (lost-model finder).

## 6. Sound, logical switches, special functions (`:core:engine`, `:core:audio`, `:core:runtime`, UI in `:feature:functions`)

All app-side, evaluated on every live tick inside the foreground service.

- **Text templates:** `Battery {RxBt} volts`, `{Alt:0} metres`, `{T1}`, `{FM}`, `{model}`, `{LQ}`. `{name}` resolves sensors, inputs (`{SA}`, `{Thr}`), channels (`{CH3}`), timers, flight mode. Optional `:precision`. Values are spoken with units.
- **Voice alerts:** text + trigger (switch position, logical switch, telemetry condition, timer event, flight-mode change, always/periodic) + repeat (once on activation / every N s while active) + priority.
- **Logical switches L1–L32:** functions `a>x a<x |a|>x |a|<x a≈x a>b a<b AND OR XOR EDGE STICKY TIMER DELTA`, optional AND-condition, duration, delay — EdgeTX semantics. They can trigger app-side actions and widgets only; the UI states clearly that they cannot drive mixes.
- **Special functions SF1–SF64:** `trigger → action (+ parameter, repeat, enabled)`. Actions: Play text, Play value, Play sound file, Background music, **Vario**, Haptic, Reset timer, Reset telemetry (min/max), Reset flight, Set media volume (from a pot), Start/stop logging, Screenshot, Screen brightness. Channel-affecting EdgeTX functions (Override, Instant trim, Trainer) are deliberately absent; the UI points to ChLock/mixes instead.
- **Vario:** continuous tone synth from vertical speed (sensor selectable; derive from altitude if needed). EdgeTX-style parameters: dead band min/max, range min/max, centre silent, pitch at zero / at max, repeat. Sink = low continuous tone, climb = rising beeps.
- **Audio engine:** Android text-to-speech (detect engine and language; settings show a clear warning if none), tone synth with low latency, user sound files from `…/OpenAX12/sounds/`, priority queue (alarms pre-empt), audio focus, per-category volume, haptics. Trim beeps with a distinct centre tone, timer countdown voice, switch-position announcements (optional).

## 7. Flight modes and flaps (compiled to firmware)

- **Flight modes:** one mode switch (2- or 3-position) selects the mode; mode 0 is the default. Per mode: name, per-channel offset (trim/camber/elevator compensation), per-channel rate (dual-rate slot on the same switch), transition time (slow), announce by voice. Compilation: for each channel with a non-zero offset add one mix line `channel += modeSwitch` through a **custom 3-point curve** whose points are the per-position offsets, with slow up/down = transition time. Rates use the channel's dual-rate slots. Curves are allocated from the 18 and shared when identical.
- **Flaps / Wing wizard:** flap control (switch positions or slider), flap channels, per-position deflection, speed, elevator compensation; flaperons; aileron differential; butterfly/crow (source = throttle stick or slider: flaps down, ailerons up, elevator compensation curve); V-tail and elevon mixes.
- **Managed lines:** everything the compilers generate is recorded in `ModelExtras.managed` (mix keys `(chIdx, srcIdx)`, curve indices, dual-rate slots). Recompiling removes the old managed items first. A dry-run diff is shown before applying. Conflicts (a user mix already uses the same `(chIdx, srcIdx)`, no free curve/slot) are reported, never silently overwritten.
- The simulator's mixer must reproduce these mixes so the result is checkable on the emulator's channel monitor.

## 8. System (`:feature:system`) — not per model

- Radio: stick mode, alarm voltage, RF module mode (internal/external/off), stick calibration (start/stop + state), reboot RF module, USB serial passthrough, restore defaults (double confirm).
- ELRS: parameter menu browser (request menu, folders, option/number items, commands, ack), link status (good/bad packets, model mismatch).
- Pre-flight check overview and "skip" action; per-model checklist text.
- App: theme, language of speech, volumes, units (metric/imperial), haptics, keep screen on, touch-lock behaviour, radio backend (Auto / SDK / Simulator), storage location info, backup/restore of the whole library (zip).
- About / diagnostics: SDK version, firmware info (read-only), connection state and last errors, raw source/channel monitor, CRSF frame counters, list of `docs/ASSUMPTIONS.md` checks, export diagnostics. A clear hint when the serial port cannot be opened ("close the stock RadioMaster app") and that firmware updates are done in the stock app.
- **Simulator panel** (only with the simulator backend): drag sticks, flip switches, turn knobs, set telemetry values, drop/restore the link.

## 9. Runtime and safety

- `RadioService` (foreground, sticky) keeps the radio connection, runtime engine and audio alive while other apps are in front. Notification shows model, link and timers.
- Startup: init radio → read device config → reconcile model library → start runtime. Connection state machine is visible in the UI (connecting / ready / error with reason).
- Writing to the device or switching models while linked asks for confirmation. Destructive actions are double-confirmed.
- Touch lock (bottom bar): blocks touches until long-press unlock.
- If the app or service dies, the radio keeps flying on the last saved firmware config (rule 1).
